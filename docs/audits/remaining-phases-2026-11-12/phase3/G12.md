## PH3-G12-001

**Reject caller-minted verified witness fields at inspection creation**

Priority: **P0** · status: **OPEN** · type: `CODE_DEFECT` · evidence: `TARGETED_RUNTIME_OBSERVATION`

**Observed / missing:** R37 uses ordinary inspection creation to persist witnessParties containing isVerified=true, AUTHENTICATED_ATTESTATION and another signedByUserId. The dedicated witness endpoint is protected, but the creation path serializes arbitrary runtime objects wholesale. This proves forged verified-looking metadata, not that it legally closes a project.

**Required correction:** Validate and allowlist creation-time witness assignments; reserve all verification/signature/principal/time fields for the trusted attestation command. Quarantine ambiguous existing records with provenance review rather than treating flags as evidence.

**Acceptance:** Use actual HTTP member creation with injected/nested signature fields and typed legitimate assignments. Caller fields must reject or be safely discarded; only independently authenticated witness transitions may create authoritative verification records.

**Runtime observations:** `R37` in [API/worker observations](../evidence/probe-results.json) or [browser observations](../evidence/offline-results.json). These are observation IDs, not one test or one independent bug each.

## PH3-G12-002

**Bind attestations to an exact immutable inspection and declaration**

Priority: **P1** · status: **OPEN** · type: `CODE_DEFECT` · evidence: `SOURCE_CONFIRMED`

**Observed / missing:** The dedicated witness command checks active independent party authority and assignment and distinguishes attendance, which is positive. Its record is a JSON witness append without a complete content digest/version/declaration and fresh-assurance contract for precisely what was attested.

**Required correction:** Create an immutable attestation record bound to inspection/evidence revision, digest, declared scope, trusted principal/delegation and proof time. Capture explicit informed consent; material inspection changes require a new version and re-attestation, not mutation of old claims.

**Acceptance:** Test stale/changed content, wrong party/revision, repeated signing, expired proof, revoked delegation and attendance-only records. Verify export/UI identifies exact attested content and never relabels attendance as a signature.
