## PH3-G08-001

**Make atomic asset import actually atomic and preview accurate**

Priority: **P1** · status: **OPEN** · type: `CODE_DEFECT` · evidence: `TARGETED_RUNTIME_OBSERVATION`

**Observed / missing:** R42 requests atomic=true, imports a valid first row, then fails an invalid second tag; the first asset remains committed. importAssets opens an outer transaction but createAsset opens independent transactions. Preview also omits the real AssetTagSchema check and UPDATE conflict strategy does not implement a controlled update.

**Required correction:** Use one transaction/client and shared project lock for atomic import, with row savepoints only for explicitly non-atomic mode. Share row validation between preview and commit; implement or reject UPDATE and bind preview to current versions.

**Acceptance:** Test a later invalid/duplicate row, DB failure, concurrent import, scope denial and retry. Atomic failure leaves zero assets/events/requirements; non-atomic mode reports exact committed rows.
