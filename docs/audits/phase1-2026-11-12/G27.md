### PH1-G27-001 — P0 / REPRODUCED: Audit immutability can be bypassed through partition access

**Source:** [packages/db/migrations/0000_complete_v021_schema_and_rls.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0000_complete_v021_schema_and_rls.sql), [packages/db/migrations/0001_rls_and_constraints.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0001_rls_and_constraints.sql), [packages/db/migrations/0004_perfect_10_hardening.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0004_perfect_10_hardening.sql), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** The database runtime role can alter audit metadata or delete history through child tables. The hash verifier accepts the changed IP and the missing tail. Parent append-only protection is not end-to-end immutable audit storage.

**Required correction:** Share the PH1-G26-001 ACL/policy correction; add trusted externally anchored chain heads/counts and immutable export/checkpoint policy, with a narrowly reviewed operator recovery path. Do not describe an unanchored mutable database hash chain as tamper-proof.

**Acceptance:** Direct partition mutation denies under runtime roles; independently anchored verification detects prefix/tail removal, rewritten history and payload/metadata changes. Restore/retention preserves checkpoint provenance.

**Executed local observations:** P01, P02, P03, P04. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G27-002 — P1 / REPRODUCED: Verifier omits genesis/head expectations and some security metadata

**Source:** [packages/db/migrations/0004_perfect_10_hardening.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0004_perfect_10_hardening.sql), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts), [scripts/run-restore-drill.sh](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/scripts/run-restore-drill.sh).

**Observation and limits:** The verifier skips predecessor comparison for the first returned event and has no trusted expected final head/count. Canonical hash excludes IP/user_agent/chain_seq. IP tampering and deletion of an organisation's only event were accepted; explicit sequence manipulation can break ordering.

**Required correction:** Version the canonical event envelope and verification contract; define genesis, monotonic ordering, hashed security metadata and independently stored head/count checkpoints. Cover nullable/global/platform events instead of iterating only existing organisation IDs.

**Acceptance:** Known-good vectors and corruption tests for first/middle/last events, metadata, duplicate/out-of-order sequence, global events and restored partitions. Verify historical hash-version compatibility.

**Executed local observations:** P03, P04, P05. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G27-003 — P1 / REPRODUCED: Secret redaction is shallow and does not cover all persistence surfaces

**Source:** [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts), [apps/api/src/common/interceptors/idempotency.interceptor.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/interceptors/idempotency.interceptor.ts).

**Observation and limits:** redactSensitiveFields removes a short set of top-level exact names but preserves nested otp and authToken fields. Outbox payloads are not redacted by this function. Separately, actual MFA factor material is captured by generic idempotency receipts.

**Required correction:** Define event/response allowlists and recursively enforce sensitive-field/value policy before logs, audit, outbox, traces and receipts. Exclude secret-bearing auth outputs through a dedicated contract. Test provider errors, nested objects, URLs and aliases without relying on key-name matching alone.

**Acceptance:** Canary credential tests across all persistence/export/telemetry paths find no raw OTP, factor secret, backup code, token, key or private signed URL; legitimate audit attribution and domain fields remain useful.

**Executed local observations:** P09, P21. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G27-004 — P1 / REPRODUCED: Domain payloads can replace trusted event envelope identities

**Source:** [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts), [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts).

**Observation and limits:** withTenantTransaction spreads afterJson after trusted orgId/actorUserId/entity fields. A real emitted fixture stores forged org and actor IDs in payload_json, although the outbox row retains the real tenant and the poller later overwrites orgId. This is not a proved worker cross-tenant write.

**Required correction:** Separate immutable envelope from validated versioned domain payload, reserve identity/correlation fields and validate at producer and consumer. Never derive authority from payload-provided actor or project when the row/resource is authoritative.

**Acceptance:** Forged reserved fields, unknown schema versions and tenant/project/resource mismatches reject or quarantine without effects; actual emitted jobs retain the correct actor, event and request provenance.

**Executed local observations:** P10. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G27-005 — P1 / SOURCE_CONFIRMED: Non-authentication errors and health responses expose unreviewed details

**Source:** [apps/api/src/common/filters/problem-json.filter.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/filters/problem-json.filter.ts), [apps/api/src/modules/health/health.controller.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/health/health.controller.ts), [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts).

**Observation and limits:** Authentication errors now have useful redaction, but the general filter logs raw exception messages/stacks and the public health error returns err.message. Worker/scheduler paths log raw Error objects. The inspected code has no single safe product-wide telemetry schema.

**Required correction:** Return minimal public health/liveness status, keep readiness diagnostics private and sanitised, and use bounded structured error codes across API/worker/provider/database paths. Retain safe server correlation IDs and classified internal diagnostics with controlled access.

**Acceptance:** Fault-inject database/provider/processor errors containing synthetic secrets and PII; neither client responses nor normal logs expose them. Operators can still identify failures using safe correlation and error categories.

### PH1-G27-006 — P1 / SOURCE_CONFIRMED: Audit and notification coverage is inconsistent across business commands

**Source:** [apps/api/src/modules/organisations/organisations.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/organisations/organisations.service.ts), [apps/worker/src/event-registry.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/event-registry.ts), [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts).

### PH1-G27-007 — P1 / OPERATIONAL_GATE: Security headers and browser isolation need a deployed enforcement contract

**Source:** [apps/api/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/main.ts), [apps/web/next.config.mjs](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/web/next.config.mjs), [apps/api/src/modules/documents/documents.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/documents/documents.service.ts), [infra/terraform/main.tf](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/infra/terraform/main.tf).

**Observation and limits:** Auth/guest no-store/no-referrer and document-stream sandboxing exist. Whole-application CSP, framing isolation, HTTPS/HSTS and proxy/cache behavior are not established by source snippets or local HTTP. Terraform is a partial deployment scaffold, not a verified ingress.

**Required correction:** Define and enforce headers at the appropriate application/ingress boundary, private API/cache policy, trusted proxy/cookie scope and safe embedded document behavior. Validate actual deployment rather than marking absent app headers as proof the proxy is unsafe.

**Acceptance:** Real HTTPS browser tests for hostile origins/framing, cookies, cached tenant data, token/referrer leakage, content embedding and logout/storage-loss; capture actual response headers and proxy configuration.

### PH1-G27-008 — P1 / SOURCE_CONFIRMED: Observability is primarily console output, without demonstrated actionable SLOs

**Observation and limits:** Inspected runtime uses console output for queue/scheduler failures and fixed denial-persistence diagnostics. There is no demonstrated end-to-end metrics/tracing/alert pipeline for oldest outbox age, dropped denials, stalled jobs, queue retries, pool saturation or per-tenant delivery.

### PH1-G27-009 — P1 / SOURCE_CONFIRMED: File/converter sandbox limits need operating-system enforcement

**Source:** [apps/worker/src/queues/file.processor.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/file.processor.ts), [apps/worker/src/queues/format-converter.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/format-converter.ts), [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts).

**Observation and limits:** Scans use byte/page/object/time limits and fail closed on unavailable ClamAV; production now requires qpdf. The xref counter counts only lines containing offset =, so compressed-object entries need explicit accounting. Subprocess execution has time/output limits but no shown memory/cgroup boundary, and image/office conversion decodes untrusted content in shared worker processes.

**Required correction:** Isolate parsers/converters with process/container memory/CPU/pid/disk/network limits and patched tools. Enforce decoded image/archive complexity, temp cleanup and independent scanner health/signature freshness. Preserve tested byte limits and immutable storage verification.

**Acceptance:** Resource-exhaustion, malformed/polyglot/archive/image/PDF cases terminate within budgets without killing other tenants or returning READY. Actual ClamAV/qpdf/converter and storage acceptance is separate from programmable fixtures.

**Source:** [packages/db/migrations/0039_g01_independent_identity_recovery.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0039_g01_independent_identity_recovery.sql), [infra/terraform/main.tf](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/infra/terraform/main.tf), [apps/api/src/modules/identity/auth-security.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/identity/auth-security.ts).

**Observation and limits:** Separate reviewer/executor roles and startup privilege validation are implemented. Actual human identity, secrets/KMS access, rotation/compromise drills, SIEM retention/privacy and incident response are not established by this code audit.

**Required correction:** Approve the threat model and legal/operational policies, provision independent named IAM, test least privilege and break-glass accountability, rotate all relevant keys and rehearse tenant-safe incident handling with evidence preservation.

**Acceptance:** Independent security/operations/legal acceptance of deployed roles, key lifecycle, time synchronisation, alert escalation, retention and incident procedures at the exact release. No fixture or sole implementer can supply that approval.

## What must be achieved before production

1. Runtime SQL cannot bypass audit/tenant protection through any child/default/future partition or privileged function.
2. Versioned canonical audit verification and independent immutable checkpoints detect metadata tampering and first/middle/tail deletion across restore/retention.
3. Secret/PII canaries pass all API/worker/log/audit/outbox/receipt/trace/error/export paths while preserving safe attribution.
4. Mandatory critical event coverage, sampling limits and event-store outage policy are documented and exercised.
5. Actual HTTPS ingress/browser enforces approved security headers, cache/cookie/origin/framing/document isolation and private diagnostic access.
6. Malicious file/parser/converter cases run under OS resource/network isolation and actual scanner/storage verification.
7. Metrics, correlation, tracing, SLO alerts and on-call runbooks work under real dependency/queue/replica failures with bounded cardinality.
8. Independent IAM/key rotation/incident/privacy/retention/legal and operating acceptance exists for the exact deployed release.
