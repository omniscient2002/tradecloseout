## Findings and required corrections

### PH1-G02-001 — P1 / REPRODUCED: Document row and read-only scopes remain unenforced on major paths

**Source:** [apps/api/src/modules/documents/documents.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/documents/documents.service.ts), [packages/db/src/project-authority.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/project-authority.ts), [apps/api/src/common/guards/permission.guard.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/guards/permission.guard.ts).

**Observation and limits:** A member with documentIds restricted to A lists A and B and reads B. A member with mode READ_ONLY can delete a document. The helper understands mode, but the guard checks only readOnly===true and several document services never call the helper. This leaves original G02-002 incomplete.

**Required correction:** Apply one validated scope policy to lists/details/versions/preview/download/upload/replace/delete/restore/import and relationships, including indirect asset/requirement scopes. Enforce it inside the transaction before reads/writes or pagination/counts escape.

**Acceptance:** Actual HTTP and restricted DB positives/negatives for every scope dimension and route alias; mixed bulk atomicity, current grant/member revocation, immutable evidence and legitimate scoped workflows remain correct.

**Executed local observations:** P22, P23. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G02-002 — P1 / REPRODUCED: Bulk review decisions lose project resolution and current membership checks

**Source:** [apps/api/src/common/guards/permission.guard.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/guards/permission.guard.ts), [apps/api/src/modules/reviews/reviews.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/reviews/reviews.service.ts), [apps/api/src/modules/reviews/reviews.controller.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/reviews/reviews.controller.ts), [packages/db/src/project-authority.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/project-authority.ts).

**Observation and limits:** The real bulk guard allows a QC actor with removed project membership and leaves projectId unresolved. bulkDecisions then passes the same context to decideReview; the project authority helper returns early without projectId. An assigned old review is successfully REJECTED and persisted after membership removal.

**Required correction:** Resolve and authorise each review project/resource under the decision transaction, including current membership/scope/role and project lifecycle. Do not reuse a projectless context for mixed-project commands. Define atomic versus per-item semantics and report rejected rows accurately.

**Acceptance:** Single and mixed-project bulk decisions after removal/scope change deny; legitimate current assignments succeed. Test APPROVE, REJECT and changes requests through all route aliases with real evidence where approval is claimed.

**Executed local observations:** P24. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G02-003 — P1 / REPRODUCED: Malformed or unknown restrictive scope shapes can widen access

**Source:** [packages/db/src/project-authority.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/project-authority.ts), [apps/api/src/modules/projects/projects.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/projects/projects.service.ts).

**Observation and limits:** assertMemberResourceScope ignores unknown keys and accepts readOnly as a string without treating it as a restriction. Scope JSON has no single validated runtime contract at creation/read boundaries. The probes are helper-level; they do not establish a public scope-edit endpoint exploit.

**Required correction:** Define a strict versioned scope schema and reject unsupported dimensions, types, modes and invalid dates/UUIDs. Quarantine ambiguous legacy scopes or deny until reconciled; never interpret malformed restrictive data as unrestricted access.

**Acceptance:** Property/table-driven scope validation and real HTTP list/write tests for unknown keys, empty arrays, string booleans, dates, nested objects, combined dimensions and legacy versions.

**Executed local observations:** P11, P12. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G02-004 — P2 / SOURCE_CONFIRMED: Org-wide capability tables and project-membership enforcement still conflict

**Source:** [apps/api/src/common/guards/permission.guard.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/guards/permission.guard.ts), [apps/api/src/modules/projects/projects.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/projects/projects.service.ts).

**Observation and limits:** The runtime tables still grant org-wide A/Y access to several non-admin roles; the rewritten guard generally requires project membership for every non-owner/admin target regardless of evaluation.scope. Project listing and detail can therefore disagree, and the separate specification engine remains present.

**Required correction:** Approve one role/scope policy, reconcile runtime and specification evaluators and enforce it consistently across list/detail/artifact routes. Do not silently broaden reads to fix denied workflows or remove legitimate ALL grants without a policy decision.

**Acceptance:** Complete org-role/project-role matrix including unassigned PM/DOC/AUDITOR, assigned reviewer, org-wide download toggle, no-role/unknown-role and guests; intended positive workflows and deny cases agree with the approved contract.

### PH1-G02-005 — P1 / SOURCE_CONFIRMED: Resource lookup is an incomplete string-based route heuristic

**Source:** [apps/api/src/common/guards/permission.guard.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/guards/permission.guard.ts), [apps/api/src/modules/reviews/reviews.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/reviews/reviews.service.ts).

**Observation and limits:** Resolution uses URL substrings, selected UUID parameter names and body array fields. The bulk review gap demonstrates an uncovered shape. Scalar body IDs and other resource families/aliases require coverage; plain authority errors can still become generic 500 responses.

**Required correction:** Use explicit route resource metadata or typed command/resource resolvers, validate all identity-bearing inputs before SQL, and map changed/denied authority to stable non-disclosing domain responses. Revalidate nested parent-child project consistency in services.

**Acceptance:** Inventory every registered business route, including bulk, export, commissioning, direct IDs and nested aliases; malformed scalars/arrays/UUIDs return controlled 4xx before lookup, and wrong-project/tenant objects never disclose existence.

### PH1-G02-009 — P1 / SOURCE_CONFIRMED: Project lifecycle is not a universal write authorisation gate

**Source:** [apps/api/src/common/guards/permission.guard.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/guards/permission.guard.ts), [packages/db/src/project-authority.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/project-authority.ts), [apps/api/src/modules/documents/documents.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/documents/documents.service.ts), [apps/api/src/modules/assets/assets.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/assets/assets.service.ts).

**Observation and limits:** The guard and shared project-authority helper do not enforce project status. Some domain writers take explicit lifecycle locks, while document soft delete/restore and selected asset operations do not share a universal gate. Owner/Admin capability must not override CLOSED/SUSPENDED baseline policy.

**Required correction:** Inventory every write, distinguish permitted administrative aftercare from baseline/evidence changes, and enforce the approved project state under the shared project lock inside each command. Add the same check to bulk and worker-derived mutations where applicable.

**Acceptance:** Table-driven CLOSED/SUSPENDED/CANCELLED/ARCHIVED positive and negative HTTP/DB tests for every write family, including Owner/Admin. Close-versus-write races preserve frozen accepted evidence and require formal reopening where specified.

## What must be achieved before production

1. Original G02-001..017 tests use real typed responses, valid baseline fixtures and positive/negative HTTP assertions; all changed claims are revalidated.
2. One approved permission policy governs org/project/guest roles and scope; valid ALL/SCOPED positive workflows match list/detail/artifact behavior.
3. Every direct/nested/bulk route resolves actual resource ownership and validates all identity-bearing inputs before SQL.
4. Member/grant restrictions cover every row, count, search, association, artifact, mutation and indirect relationship; malformed restriction data fails closed.
5. Each bulk item revalidates current authority inside its transaction; remove/demote/scope-change/close/tenant-switch races deny stale work.
6. Legitimate supplier/client/consultant/contractor workflows pass without broadening authority, accepting status-only evidence or leaking internal identities.
7. All denied outcomes are safe controlled 4xx responses with appropriate bounded redacted telemetry; no missing permission is hidden by a 500.
8. Exact-head typecheck/build/full/security/RBAC/browser/provider/delegation evidence passes independently; no standalone merge of the stacked candidate.
