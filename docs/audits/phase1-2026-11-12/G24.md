## Findings and required corrections

### PH1-G24-001 — P1 / REPRODUCED: Scheduler leases allow overlapping execution after expiry

**Source:** [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** A real Redis test holds one callback longer than its one-second lease; a second invocation enters the same job while the first is still active. The Lua release correctly avoids deleting another owner's lock, but there is no renewal or durable fencing token.

**Required correction:** Use renewed ownership with safe cancellation and durable per-effect fencing/idempotency. Completion markers and TTLs alone cannot prevent an expired worker from committing. Define Redis outage/restart behavior and job-specific maximum duration.

**Acceptance:** Real multi-worker TTL expiry, long pause, Redis loss/failover and stale-owner completion drills yield one effective business outcome, and a stale worker cannot commit after ownership changes.

**Executed local observations:** P18. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G24-002 — P1 / REPRODUCED: Owner digest discovery returns zero recipients under runtime RLS

**Source:** [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** Global owner discovery joins FORCE-RLS memberships without tenant context and finds zero rows despite active fixture organisations. A weekly period can be marked complete after doing no useful work.

**Required correction:** Discover eligible tenant IDs through the reviewed system boundary and load owner membership in each scoped transaction. Reconcile expected versus actual recipients and alert on missing owners; do not grant BYPASSRLS.

**Acceptance:** Multiple active/suspended/owner-transferred tenants produce only correct recipients under actual tc_app, with accurate counts, dedup and delivery evidence.

**Executed local observations:** P15. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G24-003 — P1 / SOURCE_CONFIRMED: Outbox and processor retries lack complete dead-letter/recovery handling

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [apps/worker/src/event-registry.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/event-registry.ts), [apps/worker/src/queues/portable-archive.processor.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/portable-archive.processor.ts).

**Observation and limits:** Outbox rows stop being selected after attempts reaches five, without a shown durable dead-letter/recovery workflow. Archive/format terminal-failure handling is less complete than file/PDF handling. Unknown event types become stranded attempts rather than actionable operator work.

**Required correction:** Define explicit retry/dead-letter/blocked states, classified transient/permanent errors, bounded exponential backoff, durable reason/next-attempt timestamps, safe replay tooling and alerts. Reconcile terminal job state to the domain object for every queue.

**Acceptance:** Exhaust retries, unknown schemas, storage failures, process crashes and replay through real BullMQ/PG; each job has a visible recoverable terminal state, no permanent GENERATING/PROCESSING silence and no duplicate artifacts.

### PH1-G24-004 — P1 / SOURCE_CONFIRMED: Outbox polling holds database locks across Redis I/O and catches SQL without savepoints

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts).

**Observation and limits:** The poller locks a tenant batch, awaits queue.add and updates rows in one transaction. A SQL failure caught inside the loop can leave PostgreSQL aborted; the subsequent attempts UPDATE cannot repair it without a savepoint. Redis stalls hold database resources.

**Required correction:** Use a deliberate claim/lease/dispatch/ack protocol with durable dedup keys, short DB transactions and per-row savepoints where appropriate. Coordinate queue admission with outcome reconciliation; do not claim distributed exactly-once from a local transaction.

**Acceptance:** Inject queue-add acknowledgement loss, SQL error mid-batch, Redis timeout and process death before/after commit. Other tenants continue, rolled-back dispatches retry safely and no locks/connections remain stranded.

### PH1-G24-005 — P1 / SOURCE_CONFIRMED: Generic notification delivery is unbounded in retries and performs provider I/O under locks

**Source:** [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts), [apps/worker/src/notification-delivery.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/notification-delivery.ts).

**Observation and limits:** The dispatcher holds row locks and a transaction while up to 25 provider calls each wait up to ten seconds. Failures remain QUEUED with no shown per-recipient retry/backoff/dead-letter ledger. Old failures can monopolise the first batch; acknowledgement means gateway acceptance, not final delivery.

**Required correction:** Claim short-lived work, perform bounded external I/O outside DB locks, persist retry schedule/attempt/result/receipt state and enforce fairness. Require gateway idempotency and explicitly separate accepted, delivered, bounced and failed outcomes.

**Acceptance:** Provider outage/accepted-timeout/duplicate/bounce tests, >25 queued failures, multiple tenants and quiet hours prove bounded lock time, fair progress and accurate user-visible delivery state.

### PH1-G24-006 — P1 / SOURCE_CONFIRMED: Scheduler cycle overlap and failure coupling can starve independent jobs

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** setInterval starts async cycles without awaiting the previous cycle. One catch wraps the entire sequence, so an early task failure skips later tasks for that cycle. Daily successful completion markers can also defer newly discovered/corrected work until the next slot.

**Required correction:** Use non-overlapping orchestration or isolated durable repeatable jobs, per-task failure boundaries, explicit catch-up semantics and tenant-level progress. Persist sufficient execution state to resume partial work rather than treating zero rows as universal success.

**Acceptance:** Slow/failing tenant tasks and process restarts do not prevent auth reconciliation, security checks or other tenants from progressing; missed schedules catch up exactly according to the documented policy.

### PH1-G24-007 — P1 / REPRODUCED: READY finalisation can fail after successful scan because quota SQL is invalid

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts), [apps/worker/src/queues/file.processor.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/file.processor.ts).

**Observation and limits:** The file processor invokes the broken storage quota reconciliation inside its final state transaction. Retrying the same bytes cannot fix a deterministic 42804 error. This is the worker impact of PH1-G26-002, not a separate scanner failure.

**Required correction:** Share the typed quota correction and define deduplicated finalisation keyed to the exact object/provider version. Reconcile stuck files and counters; persist a classified actionable failure after bounded retries.

**Acceptance:** Actual scan-to-READY/QUARANTINED/FAILED transitions plus duplicate jobs and crashes preserve verified evidence and exact usage; no success is reported before the final transaction commits.

**Executed local observations:** P06. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G24-008 — P1 / SOURCE_CONFIRMED: Expired generic idempotency claims have no outcome reconciliation

**Source:** [apps/api/src/common/interceptors/idempotency.interceptor.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/common/interceptors/idempotency.interceptor.ts), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** The cleanup deliberately deletes only completed expired receipts. An unresolved response_status=0 claim remains blocked indefinitely if a process dies or receipt persistence fails after the domain commit. This fail-closed behavior is safer than deleting unknown outcomes but is not a complete recovery mechanism.

**Required correction:** Link command receipts to durable business outcomes, implement authorised idempotent reconciliation and expose pending/unknown status. Never retry an irreversible command solely because a receipt expired; separately fix secret-bearing response capture.

**Acceptance:** Crash before/after business commit and before/after receipt update, then restart/reconcile: one effect, a discoverable result and no permanently unresolvable client command.

### PH1-G24-009 — P1 / SOURCE_CONFIRMED: Resource, tenant and event schema validation must cover every queue

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [apps/worker/src/event-registry.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/event-registry.ts), [apps/worker/src/queues/format-converter.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/format-converter.ts).

**Observation and limits:** File jobs validate important immutable identity fields and bounded streams; other queues receive job.data directly, including local filesystem paths for conversion. Outbox payloads are not a typed authority envelope and format enqueue/provenance is not established end to end.

**Required correction:** Use per-queue strict versioned schemas, resolve row/resource tenant and immutable version, constrain local paths to owned temporary roots and separate queue producer/consumer credentials. Reject unknown/mismatched events before effects; protect reserved envelope fields.

**Acceptance:** Malformed, cross-tenant/project, stale-version, arbitrary path and oversized jobs reject/quarantine. Legitimate producers emit actionable payloads and every consumer verifies the same source provenance.

### PH1-G24-010 — P1 / SOURCE_CONFIRMED: Shutdown does not explicitly drain in-flight pollers/schedulers

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** Signal handling clears intervals and closes BullMQ workers/queues, then ends PG/Redis and exits. It does not track and await already-running pollOutbox/runScheduledCycles invocations or define a bounded abort deadline for those independent operations.

**Required correction:** Track active work, stop new claims, renew/transfer or cancel ownership safely, drain or abort all execution families with a deadline, then close dependencies. Record uncertain outcomes for reconciliation instead of relying on process exit.

**Acceptance:** SIGTERM during provider I/O, DB commit, queue add and scheduled reconciliation leaves no lost claim, unacknowledged completed effect or poisoned client; restart recovers according to durable state.

### PH1-G24-011 — P1 / SOURCE_CONFIRMED: Production readiness checks do not cover the whole processing chain

**Source:** [apps/worker/src/worker-startup-security.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/worker-startup-security.ts), [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [apps/worker/src/queues/file.processor.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/file.processor.ts), [apps/worker/src/queues/format-converter.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/queues/format-converter.ts), [apps/api/src/modules/health/health.controller.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/health/health.controller.ts).

**Observation and limits:** Worker startup now validates mode/URLs/actual DB role, pings Redis and requires qpdf. It does not establish complete S3 permissions/versioning, scanner/signature freshness, every required converter, writable/disk budget, queue lag or separate worker readiness status.

**Required correction:** Add scoped dependency/permission probes and ongoing readiness/metrics for the actual enabled processing capabilities; disable unsupported conversions explicitly. Keep liveness distinct from readiness and degraded provider delivery.

**Acceptance:** Misconfigured IAM/bucket/versioning, unavailable scanner/converter, full temp disk, Redis loss and DB failover produce safe readiness/operational signals and fail closed without accepting unusable work.

### PH1-G24-012 — P1 / OPERATIONAL_GATE: Scale, fairness and provider acceptance remain deployment gates

**Source:** [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts), [apps/worker/src/notification-delivery.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/notification-delivery.ts), [packages/db/src/auth-delivery.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/auth-delivery.ts).

**Observation and limits:** Polling iterates all organisations, locks batches and uses shared fixed worker concurrency. Real tenant load, large package CPU/memory pressure, queue persistence/failover and actual vendor throughput/rate budgets have not been accepted in this audit.

**Required correction:** Define per-tenant admission/concurrency/fairness, queue retention and Redis durability, retry/spend budgets, event lag SLOs and operator replay controls. Verify old/new worker compatibility and rolling deployment recovery.

**Acceptance:** Load/failure/chaos runs with representative data meet published SLOs and resource budgets. Real storage/scanner/mail/SMS receipts and alert/runbook drills supplement fixture tests; no fixture is relabelled as production acceptance.

## What must be achieved before production

1. Every queue has strict schemas, authoritative tenant/object/version binding and a legitimate producer-to-consumer positive test.
2. Durable admission, retries/backoff, terminal state, dead-letter inspection and authorised replay are implemented and visible for every processing family.
3. Real multi-worker lease expiry/Redis loss/crash/rolling deploy tests prove fencing and one effective business outcome.
4. No provider/Redis I/O unnecessarily holds tenant DB locks; SQL errors and uncertain commits reconcile without blocking other tenants.
5. Scan/package/archive/conversion outcomes and quota/accounting remain atomic, immutable and idempotent after duplicate jobs or failure.
6. Scheduler overlap, per-task/per-tenant failures, missed-slot catch-up, quiet hours and incomplete-recipient conditions have explicit tested semantics.
7. SIGTERM/timeout drains or safely abandons every active poller/scheduler/job, and restart recovers unknown outcomes.
8. Actual dependency readiness, storage/scanner/converter/provider delivery, load/fairness/resource SLOs and alert/replay runbooks are accepted.
