### PH1-G26-001 — P0 / REPRODUCED: Audit partitions bypass tenant RLS and append-only permissions

**Source:** [packages/db/migrations/0000_complete_v021_schema_and_rls.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0000_complete_v021_schema_and_rls.sql), [packages/db/migrations/0001_rls_and_constraints.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0001_rls_and_constraints.sql), [packages/db/migrations/0004_perfect_10_hardening.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0004_perfect_10_hardening.sql).

**Observation and limits:** All four audit children grant tc_app SELECT/UPDATE/DELETE with neither enabled nor forced RLS. A no-context parent query returns zero rows while a direct child query returns a tenant event; direct child UPDATE and DELETE succeed. This is a restricted-database-role boundary failure, not a demonstrated SQL-injection entry point.

**Required correction:** Revoke direct child access, constrain the parent command surface, and apply independently verified child policies/triggers if any direct access is necessary. Cover default, existing and future partitions and default privileges. Review inherited statement versus row triggers; protect TRUNCATE and table ownership as separate privileges.

**Acceptance:** Under actual tc_app, direct child SELECT/INSERT/UPDATE/DELETE/TRUNCATE cannot disclose or change another tenant or bypass immutability. Parent authorised insert/read works. Fresh/upgrade and newly attached partition tests must inspect ACLs/policies and execute negative SQL.

**Executed local observations:** P01, P02, P03, P04. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G26-002 — P1 / REPRODUCED: Storage quota reconciliation has an executable SQL type error

**Source:** [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts), [apps/worker/src/main.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/main.ts).

**Observation and limits:** reconcileStorageQuotaOnFileStatusChange writes GREATEST(...)::text into BIGINT value. PostgreSQL rejects with 42804. The file worker calls this while finalising READY, so the same transaction can roll back a successfully scanned file.

**Required correction:** Use correctly typed bigint/numeric arithmetic, validate size/delta, and reconcile the transition once against immutable object/version identity. Preserve atomic file state, usage counters and audit; provide reconciliation for previously stuck jobs.

**Acceptance:** Actual migrated PG16 finalisation, duplicate scan, retry, quarantine, delete/restore and rollback cases preserve exact non-negative byte counts. Scanner/storage success alone must not be reported as persisted READY.

**Executed local observations:** P06. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G26-003 — P1 / REPRODUCED: Drizzle definitions and deployed SQL disagree across 33 represented tables

**Source:** [packages/db/src/schema.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/schema.ts), [packages/db/migrations/0000_complete_v021_schema_and_rls.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0000_complete_v021_schema_and_rls.sql).

**Observation and limits:** Column inventory finds 33 represented tables with missing or extra columns. Examples: nonexistent organisations.allow_generic_review, profile default_timezone/default_locale, invitation phone versus phone_e164, and project-member timestamp names. This is column drift; the probe does not claim exhaustive constraint/type parity.

**Required correction:** Inventory columns, types, nullability, defaults, constraints, indexes, FKs, policies and grants; designate migrated SQL as the baseline and reconcile the ORM explicitly. Add forward migrations only where the intended contract actually needs a schema change; do not rewrite applied checksums.

**Acceptance:** Automated fresh/upgrade schema equivalence includes the ORM contract and real queries for each supported table, with documented deliberate exclusions and no defined-but-absent runtime fields.

**Executed local observations:** P25. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G26-004 — P1 / REPRODUCED: Transaction session fences omit current account/tenant eligibility

**Source:** [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts), [apps/api/src/database/tenant-db.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/database/tenant-db.service.ts), [packages/db/src/project-authority.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/project-authority.ts).

**Observation and limits:** A valid session/generation still allows a project mutation after the organisation is suspended. The project authority helper trusts ctx.orgRole Owner/Admin without querying live membership. HTTP guards check eligibility earlier; these probes concern the later transaction boundary, not unauthenticated access.

**Required correction:** Define a common current-authority command boundary that locks and checks account, tenant, membership, role, scope and session where required. Bind the resource project to the command, with a documented exception for separately privileged system work.

**Acceptance:** Pause real authenticated commands before mutation; suspend/demote/remove/change scope on another connection and verify a clear linearization rule. No post-transition command may rely on a stale Owner/Admin shortcut.

**Executed local observations:** P13, P14. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G26-005 — P1 / SOURCE_CONFIRMED: Exactly-one-owner and organisation-member relationships remain weak database invariants

**Source:** [packages/db/migrations/0000_complete_v021_schema_and_rls.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0000_complete_v021_schema_and_rls.sql), [apps/api/src/modules/organisations/organisations.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/organisations/organisations.service.ts), [apps/api/src/modules/projects/projects.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/modules/projects/projects.service.ts).

**Observation and limits:** The unique active-owner index proves at most one owner. Generic role/transfer paths still require a shared invariant strategy. Work and project membership point to global users, which does not establish current organisation eligibility. G03 audits record corresponding service races and invalid allocations.

**Required correction:** Serialize owner transitions and enforce the final eligible-owner invariant at commit. Add reviewed membership/assignment constraints or command functions where feasible, and explicitly enforce temporal eligibility where static FKs cannot express it. Repair ambiguous legacy rows through an operator-reviewed inventory.

**Acceptance:** Concurrent transfer/demotion/removal and user deletion leave exactly one eligible owner for each active organisation. Cross-tenant or inactive assignees/project grants are rejected without fabricating replacement identity.

### PH1-G26-006 — P1 / SOURCE_CONFIRMED: Rollback failure and transaction timeout policy are incomplete

**Source:** [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts), [apps/api/src/database/tenant-db.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/database/tenant-db.service.ts), [packages/db/src/run-migrations.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/run-migrations.ts).

**Observation and limits:** General wrappers await ROLLBACK and then release without the explicit destroy-on-unknown-state logic used by the newer auth-denial writer. They do not set server-side lock/statement/idle transaction budgets or implement a common bounded deadlock/serialization policy.

**Required correction:** Preserve the original error, destroy connections whose rollback/state is uncertain, define server-side timeouts and cancellation, and retry only whole idempotent commands on classified failures. Keep external I/O outside business locks and preserve nested savepoint ownership.

**Acceptance:** Inject BEGIN/statement/COMMIT/ROLLBACK disconnects, lock timeouts and 40P01/40001; verify no idle transaction or tenant context leak, healthy pool reuse and no duplicate committed effects.

### PH1-G26-007 — P2 / SOURCE_CONFIRMED: Tenant alias validation is not applied uniformly

**Source:** [packages/db/migrations/0001_rls_and_constraints.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0001_rls_and_constraints.sql), [apps/api/src/database/tenant-db.service.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/api/src/database/tenant-db.service.ts), [packages/db/src/tenant-tx.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/tenant-tx.ts).

**Observation and limits:** The canonical conflicting-alias checker introduced in migration 0016 is used by selected later tables; many core policies still read app.current_org directly. Normal wrappers set both aliases consistently, but the database does not uniformly reject conflicting settings.

**Required correction:** Standardise tenant context and policy functions across all relevant tables and privileged functions, split self-discovery SELECT from writes where appropriate, and retain explicit token/bootstrap exceptions. Do not broaden RLS to repair a caller bug.

**Acceptance:** Test no context, conflicting aliases, pooled commit/rollback, self-membership discovery, guest/invitation token contexts and every tenant table/partition under the restricted role.

**Executed local observations:** P17. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G26-008 — P1 / REPRODUCED: Audit sequence ordering is caller-influenced

**Source:** [packages/db/migrations/0004_perfect_10_hardening.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0004_perfect_10_hardening.sql), [apps/worker/src/scheduler.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/apps/worker/src/scheduler.ts).

**Observation and limits:** The trigger keeps a caller-supplied non-null chain_seq and the DEFAULT sequence is allocated before its advisory lock. Explicit reverse sequences are accepted and cause the verifier to reject the chain. Ordinary concurrent sequence allocation ordering also needs a deterministic test; that race was not executed here.

**Required correction:** Allocate chain position inside the serialised insertion boundary, prohibit caller-controlled chain fields, define uniqueness and stable head ordering, and check genesis/head linkage. Preserve existing history through versioned migration/checkpoints.

**Acceptance:** Caller-supplied sequence/hash fields cannot corrupt ordering. Deterministic competing inserts, rollback gaps, cross-tenant concurrency and restore verification agree on the same canonical chain.

**Executed local observations:** P05. See the evidence JSON; a reproduction passing is not a repaired control.

### PH1-G26-009 — P1 / OPERATIONAL_GATE: Migration success does not establish production-safe data conversion

### PH1-G26-010 — P1 / OPERATIONAL_GATE: Backup and restore evidence is not a complete recovery contract

**Source:** [scripts/run-restore-drill.sh](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/scripts/run-restore-drill.sh), [infra/terraform/main.tf](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/infra/terraform/main.tf).

No production restore drill ran in this audit.

**Required correction:** Use a consistent snapshot/manifest, collision-resistant disposable names, cleanup traps, exact immutable storage version inventory, audited credentials and key recovery. Exercise PITR and application startup on the restored state with documented RPO/RTO.

**Acceptance:** Restore into an isolated environment; reconcile rows and object versions against the snapshot, verify audit checkpoints and RLS, prove runtime operation and timed recovery, and retain externally reviewable evidence without customer-data leakage.

### PH1-G26-011 — P1 / OPERATIONAL_GATE: Resource budgets and privileged-function ownership need deployment evidence

**Source:** [packages/db/src/run-migrations.ts](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/src/run-migrations.ts), [packages/db/migrations/0039_g01_independent_identity_recovery.sql](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/packages/db/migrations/0039_g01_independent_identity_recovery.sql), [infra/terraform/main.tf](https://github.com/omniscient2002/tradecloseout/blob/9ed91a9e96c77c9eff967f6c845d18c38fb62ac6/infra/terraform/main.tf).

Production database TLS/CA, pool budgets across replicas, owner/default ACLs, SECURITY DEFINER search_path and human reviewer/executor IAM still need evidence on the actual deployed cluster.

## What must be achieved before production

1. Fresh and supported prior-version migrations produce the reviewed schema/ORM/policy/ACL contract, with unchanged historical checksums.
2. Every tenant table and partition has executed no-context/cross-tenant/read/write/deletion negatives under the actual restricted runtime role.
3. Owner, membership, composite tenant/project relationships and current-authority invariants hold under concurrent commands and rollback.
4. Quota/state/audit/outbox transitions are typed, atomic, idempotent and reconcile correctly after crash or ambiguous commit.
5. Server-side query/lock/idle transaction budgets, cancellation, safe retries and pool cleanup are proven with fault injection.
6. Human/migration/runtime function ownership, search paths and effective grants are independently reviewed on the deployed cluster.
7. Representative legacy upgrade/quarantine impact is approved; PITR plus immutable storage and key restore meet documented RPO/RTO.
8. Exact release-head build/typecheck/full/security/RBAC/DB tests and deployment compatibility pass; user retains merge/deployment authority.
