## Controls observed working

Checksum canonicalization sorts object keys. Explicit populated PLATFORM locked fields reject conflicting overrides (C08). Installed resolution ignores later mutable TRADE input (C09). Snapshot/import writers take a project lifecycle lock, serialize imports, reject empty/unmapped input and do not silently create DT-001 placeholders. Material change code supersedes old work and invalidates affected waiver effects. These controls must be preserved.

### PH2-G06-001 — Make locked ownership and keyed-item protection monotonic

**P1 · CODE_DEFECT · OPEN · TARGETED_RUNTIME_OBSERVATION**

Source: [apps/api/src/modules/configuration/config-resolver.ts:118](https://github.com/omniscient2002/tradecloseout/blob/e1b2d9506f2f5d1cbd853a91cade58f8bab3cee4/apps/api/src/modules/configuration/config-resolver.ts#L118), [apps/api/src/modules/configuration/config-resolver.ts:202](https://github.com/omniscient2002/tradecloseout/blob/e1b2d9506f2f5d1cbd853a91cade58f8bab3cee4/apps/api/src/modules/configuration/config-resolver.ts#L202).

Observations: C01, C04 in the [shared results](evidence/probe-results.json) or [separate G03 results](evidence/g03-results.json). Probe IDs G01..G11 are observation labels, not group/finding IDs.

**Evidence and failure scenario.** C01 resolves a PLATFORM mandatory locked item, accepts ORG locked=false, then removes it at PROJECT with zero conflicts. C04 lets ORG establish a PLATFORM-owned LOCKED security field when no platform value exists. Locks depend on prior provenance or mutable item flags instead of immutable owner policy.

**Required correction.** Enforce ownerLevel independently of whether a parent supplied a value. Preserve lock/mandatory protection monotonically from the authoritative version; prevent unlock, removal, semantic replacement or approval weakening through child patches. Validate permitted change-request authority separately.

**Acceptance checks.** Test missing platform, explicit null/clear, unlock→remove/optional chains, changed document type/scope/reviewer, multiple levels and preview/apply parity. Legitimate owned edits and identical inherited values succeed without allowing child weakening.

## Production acceptance boundary

All required code/workflow items for the approved release scope need fix-SHA regression evidence and independent review on one integrated candidate. Passing the observation harness means the recorded behavior was reproduced; several observations are defects. It does **not** mean those defects are fixed. External/provider/domain/browser/operational gates remain blocked until their real evidence is supplied. No finite source audit guarantees the absence of every future defect. No application change, deployment, approval, merge, production message or destructive operation is performed by this documentation handoff.
