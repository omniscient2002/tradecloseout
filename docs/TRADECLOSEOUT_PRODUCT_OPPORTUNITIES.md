# Product opportunities and AI strategy

All rankings and price/cost ranges below are design hypotheses, not customer-validated ROI or vendor quotations. Core evidence integrity is mandatory before differentiation. These 32 opportunities extend the original prompt's themes with specific recurring jobs; many are later product extensions rather than launch commitments.

## Ranking method

Scores 1–5: pain, commercial value and differentiation are better high; adoption difficulty, effort and technical risk are worse high. Rank score = 3×pain + 3×commercial + 2×differentiation − adoption − effort − risk. It prioritises recurring valuable jobs while penalising complex adoption. It is a decision aid, not measured market data. Dependencies and full implementation families are in task specifications. No opportunity is independently authorised for coding by this document.

## Commercial model and differentiation

Test a contractor organisation subscription with active-project bands, pooled evidence storage and included external reviewers/suppliers. Charge transparently for extraordinary archive/storage or AI usage only after measuring actual cost. Avoid per-supplier fees that suppress collaboration. Offer paid onboarding for register cleanup and baseline setup; renewal depends on continuing project/aftercare work, not restricting customer exports. Keep archive export and usable post-project access terms explicit.

Test three packaging hypotheses without inventing market prices: Core evidence/handover, Team multi-project/supplier workflow, and Assurance commissioning/aftercare. Measure buyer-perceived value against documented time and return-cycle baseline. Customer interviews must distinguish ability to pay from willingness to adopt another app. AI is an assistive option, never the product's trust foundation.

The potential moat is accumulated, portable scope-specific evidence provenance plus repeatable contractor/customer conventions and supplier participation. Portability must improve trust; artificial data lock-in should not be a strategy. Deep configuration that needs implementation consulting for every project undermines the proposed small/medium contractor wedge.

## Not worth building now

Do not build full accounting/GST return filing/e-invoicing, payroll, inventory valuation, procurement payment execution, BIM authoring/clash detection, a generic workflow language, broad CRM, autonomous consultant approvals, marketplace ranking, blockchain certification, unrestricted public asset files, facial attendance, or full FM/CMMS. Do not replace client-mandated CDEs. Retire product-facing simulated success and unsupported signature certifications rather than polishing them. Reassess only against concrete customer evidence and operating economics.

## AI design guardrails

Use verified and permitted bytes only, with tenant/project ACL filtering before retrieval and again on cited results. A malicious PDF is untrusted input, including instructions it contains; models get no authority-bearing tools. Store model/prompt/parser versions, exact source version IDs, proposal JSON, citations, confidence and user disposition. No automatic approval, certification, waiver, satisfaction closure, handover acceptance or monetary edits. Deterministic rules own contractual completeness; AI can identify suspected missing content. Disable AI for customer data until processing terms, region/retention, redaction and subprocessors are approved.

Model choice is an implementation evaluation, not a fixed vendor assertion: start small OCR/text/schema models; use a larger reasoning/vision model only for difficult samples. Confidence must be calibrated on a labelled contractor corpus, not just model self-report. Initially route all output to human review; later auto-fill low-risk draft fields only if measured precision meets an explicitly agreed threshold. Critical fields always require verification.

Cost ranges are internal planning assumptions in USD per operation, excluding OCR pages, storage, messaging, taxes and provider commitments. Do not treat them as current API prices. Cap document pages, tokens, per-tenant daily spend and retries; cache by source digest, model/prompt and permission-safe result scope. Measure cost per accepted proposal and correction rate. Stop low-value features if review costs exceed saved work.

### AI01 — Document classification

- Purpose and output: Classification proposal.
- Required data: Verified version text/images and contractor document taxonomy.
- Model approach/workflow: Extract OCR/text, bounded classifier proposes doc type; intake operator accepts.
- Confidence/human verification: Never change document type used by a live rule without confirmation; measure per-class precision.
- Failure modes: Poor scans, mixed documents, misleading headings; confidence abstention and sample audit.
- Planning cost and difficulty: 0.01–0.10 USD/file; M.
- Implementation: T20; proposals never change authoritative workflow state.
- Acceptance: evaluate a labelled holdout with difficult/ambiguous scans, report precision/recall and abstention, verify citations and isolation, compare saved operator time and correction effort, and enforce spend caps.
