## PH2-NEW-007 — package attempt ownership

Confirmed source defect: queue IDs are stable across stalled delivery/retries, yet the compiler and terminal failure handler used the queue ID as the ownership fence. A duplicate could compile under the same owner, and asynchronous failure handling could affect another attempt. A successful busy skip could also acknowledge delivery before an abandoned build recovered.

Each compiler invocation now owns a distinct token. Claim, artifact reservation, publication and failure settlement use that exact token. Retryable failure releases its own claim to QUEUED; terminal failure affects only its own GENERATING claim. The event callback cannot mutate package state. Busy queue delivery is delayed without consuming the provider failure budget. Expiry uses PostgreSQL time and preserves the existing 30-minute lease; no heartbeat extension or real queue delivery acceptance is claimed here.

Each reservation now gets a distinct object key. Replaced unpublished objects retain ABORTED records with unconfirmed cleanup. This prevents an expired owner's in-flight PUT from sharing the replacement's key. Physical deletion remains a provider integration gate.

The actual compiler regression uses restricted `tc_app` in disposable PostgreSQL16 databases and a programmable HTTP storage fixture. It blocks an old PUT, rejects simultaneous same-job delivery, expires the old lease, publishes its replacement, resumes the stale PUT and verifies that stale failure cannot alter READY or its immutable object pointer. It also verifies retry release, terminal failure, replay, quota denial before PUT and retained cleanup records. Restoring shared-job ownership makes this regression fail because the duplicate unexpectedly publishes READY. This is a controlled old-behavior mutation, not an independent historical deployment reproduction.

Validation used Node22.23.5 and pnpm12.4.1. Local test URLs target only the disposable container on 127.0.0.1:55432 (`postgres` migration administrator, restricted `tc_app` runtime); no customer data or provider credentials were used.

## PH2-NEW-008 — bounded package transfers (historical PA19 subset)

After committing PH2-NEW-007 as `3cd4b8c`, the next source-confirmed defect was the compiler's unbounded source pipeline. It trusted declared source sizes for admission but checked actual bytes only after writing the complete provider body. The unused source stream could therefore exhaust disk before rejection. GET/body/PUT/HEAD also lacked compiler-selected transfer deadlines.

The compiler now applies the existing BoundedByteStream to each exact declared source size before writing. GET plus its body share one deadline; PUT and verification HEAD have deadlines. PACKAGE_TRANSFER_TIMEOUT_MS selects a positive integer deadline with a120-second technical fallback. Output read streams are destroyed after PUT settles. No database migration or permission changes are needed. Snapshot/version identity, hash/size checks, reservation and READY publication remain enforced.

An actual compiler test streams100 chunks against a one-chunk declared size and checks early failure before all chunks are consumed, no output PUT and no published pointer. Another returns a Node stream that never produces bytes and verifies timed cancellation destroys it. That test initially exposed a real additional cleanup defect: Readable.from(asyncIterable) could wait on a stalled next() despite pipeline abort. The pipeline now uses the SDK Node Readable directly and rejects unsupported stream types. The hung initial test run was terminated; only the corrected final passing run is acceptance evidence for the candidate mechanism.

Final local checks after this change: the same3 affected suites pass40 tests, workspace typecheck passes, and production build passes6 tasks (5 cached, worker rebuilt). Logs and exact changed-source hashes are stored beside the ownership evidence under transfer-* filenames. Earlier security15/RBAC8 checks apply to unchanged authority/RLS/role surfaces; these are not claims of complete current-head CI or external acceptance. Test counts overlap and must not be summed.
